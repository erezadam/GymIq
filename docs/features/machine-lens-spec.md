# מפרט פיצ'ר: זיהוי מכשיר מצילום (Machine Lens) — שלב ב.1

**תאריך:** 17/09/2026
**ענף:** `feat/machine-lens`
**סטטוס:** מפרט — טרם מומש

---

## 1. מטרה

מתאמן עומד מול מכשיר בחדר הכושר ולא יודע איזה תרגיל במערכת מתאים לו. הפיצ'ר מאפשר לו לצלם את המכשיר מתוך ספריית התרגילים, ולקבל עד 3 תרגילים מתאימים מקטלוג התרגילים הקיים — בלחיצה אחת התרגיל נוסף לאימון בדיוק כמו בחירה רגילה בספרייה.

## 2. זרימת המשתמש

1. בספריית התרגילים (`ExerciseLibrary`) מופיע כפתור מצלמה.
2. לחיצה פותחת את מצלמת המכשיר / בורר תמונה.
3. הצילום נדחס **בלקוח**: צלע ארוכה ≤ 1024px, פורמט JPEG באיכות 0.8.
4. התמונה הדחוסה נשלחת (base64) ל-Cloud Function בשם `identifyMachine`.
5. הלקוח מציג מצב טעינה; בסיום מוצג sheet עם עד 3 התאמות.
6. לחיצה על התאמה מוסיפה את התרגיל לאימון **באותו מסלול בדיוק** כבחירה רגילה בספרייה (כולל העברת `category`, `primaryMuscle`, `equipment` מלאים — חוק הברזל מ-29/01/2026).

## 3. צד שרת — Cloud Function `identifyMachine`

- **סוג:** `onCall` (callable), **דורש התחברות** (`context.auth` חובה; אחרת `unauthenticated`).
- **קלט:** התמונה הדחוסה בלבד.
- **שלב א — מודל ראייה:** הפונקציה שולחת את התמונה למודל ראייה (`gpt-4.1`) ומבקשת JSON מובנה:

| שדה | תיאור |
|-----|-------|
| `labelText` | הכיתוב שמופיע על המכשיר (אם קיים) |
| `machineType` | סוג המכשיר (למשל leg press, cable machine, `unknown`) |
| `equipmentId` | מזהה ציוד **מתוך רשימת הציוד החיה** של המערכת (מוזרמת לפרומפט) |
| `candidateExerciseNames` | שמות תרגילים מועמדים שהמודל מזהה |
| `confidence` | רמת ביטחון 0–1 |

- **שלב ב — התאמת דמיון:** הפונקציה מריצה `findSimilarExercises` — התאמה בין פלט המודל (labelText / machineType / equipmentId / candidateExerciseNames) לבין קטלוג התרגילים ב-Firestore — ומחזירה **עד 3 התאמות**, כל אחת עם `score` ו-`reasons` (הסבר טקסטואלי מדוע הותאמה).
- **הערה (חוק ברזל — רשימות ל-LLM):** רשימת הציוד המוזרמת לפרומפט נחשבת קלט מוטה-סדר; יש לערבב או להוכיח שהסדר לא מטה.

## 4. צד לקוח — הצגת תוצאות

- sheet תחתון עם עד 3 התאמות: שם התרגיל, תמונה, `score`, ו-`reasons`.
- אם זוהה `labelText` — מוצג בראש ה-sheet.
- לחיצה על התאמה ⇒ הוספה לאימון כמו בחירה רגילה; ה-sheet נסגר.
- כפתור סגירה מפורש (X ‏44x44 מינימום) + סגירה בלחיצת backdrop (חוק ברזל modals).

## 5. מגבלות מפורשות (חוקים נעולים לשלב ב.1)

1. **אין שמירת צילום בשום מקום.** לא Storage, לא Firestore, לא לוגים. הצילום חי אך ורק בזיכרון הבקשה של ה-Cloud Function ונמחק עם סיומה.
2. **מכסה: 20 זיהויים ליום למשתמש.** נאכפת בשרת דרך מסמך מונה `machineLensUsage/{uid}_{date}`. חריגה ⇒ שגיאה ייעודית והודעת מכסה בעברית בלקוח. (collection חדש ⇒ חל צ'קליסט Firestore החדש: rules + בדיקת כתיבה/קריאה בפועל.)
3. **צילום שאינו ציוד** (למשל כוס קפה) ⇒ המודל מחזיר `machineType: 'unknown'`, `confidence: 0` ⇒ אפס התאמות ⇒ הלקוח מציג "לא נמצא תרגיל מתאים" — ללא קריסה, ללא סינון שקט.
4. **כשל רשת / שגיאת שרת** ⇒ הודעת שגיאה בעברית ב-sheet, כפתור הסגירה ממשיך לעבוד.

## 6. מחוץ למפרט הזה (שלב ב.2 עתידי)

- שמירת צילומים לצפיית אדמין (לשיפור הזיהוי) — **לא** בשלב ב.1. כל מימוש של שמירה מחייב מפרט נפרד ואישור מפורש.
